# 証券外務員一種 学習アプリ 設計書

## 目的と背景
- 利用者は金融知識ゼロのエンジニア（初心者）。紙とペンを使わず、PCだけで合格レベルまで学習したい。
- 元資料: `chapters/*.md`（全10章、解説 + ○×問題 + 五肢選択問題）。
- 初心者のため、教材・問題の正誤は利用者には判断できない。**正確性の担保は全面的に作り手（Claude）の責任**。

## ゴール
1. 1回30分以内で完結する学習セッション。
2. 流れ: 解説 → 確認クイズ(採点+解説) → 解説 → 確認クイズ … を繰り返す。
3. 大事な箇所は太い赤字。【ひっかけ】は別色で目立たせる。
4. 章ごとに章末テスト（五肢選択）。合格(目安70%)で次章が解放。
5. 全章クリア後に本番形式の模擬試験（○×70問×2点 + 五肢30問×10点 = 440点、308点以上で合格）。
6. 進捗管理: どこまで進んだかを自動保存し、途中再開できる。
7. 間違えた問題の復習は**別メニュー**（セッション冒頭には出さない）。
8. 教材・問題は事実確認済みで、出典を確認できる。

## 非ゴール
- 凝った実装、サーバ、アカウント、外部ライブラリ、ネット接続前提の動作。
- 本番試験問題の再現（本番は非公開。あくまで「本番形式」）。
- 誤りゼロの保証（一次情報照合で精度を上げるが、保証はしない。下記の誤り報告で補う）。

## 素材の実数（確認済み）
- 解説の小項目（`####`）: 252 個（章別 16/21/15/26/20/41/26/17/34/36）
- ○×問題: 286 問（章別 25/30/24/28/36/23/22/28/40/30）
- 五肢選択: 87 問（章別 8/10/8/8/8/8/9/8/10/10）
- 模擬試験に必要な数（○×70 + 五肢30）は既存問題で足りる。
- ○×問題には小項目との紐付けがなく、252小項目×2問=504問には既存286問が足りない。よって確認クイズの単位は「小項目を束ねたレッスン」とし、束ねた後のレッスンごとに2〜4問を割り当てる。
- 「試験での出方」「暗記すべき数字・罰則」（`###`見出し、各章1つずつ）も独立のレッスンとして扱う。レッスン総数は束ねた結果で決まる。
- ファイル形式: `NN_xxx.md`（解説+○×。答えは `答え：○/×` と `解説：`）と `NNb_choice.md`（五肢選択。イ〜ニの正誤は解説側）の2形式を扱う。入力は `chapters/[0-9][0-9]*.md` のみ。`00_header.md`、`merge.sh`、`index.html`、`gaimuin-ichishu.md` は入力にしない。

## 構成（簡易）
- 単一の `app/index.html`（JS/CSSは同梱、外部ライブラリなし）+ `app/data.js`（`window.DATA = {...}` として教材JSONを読み込み）。`file://` でダブルクリックして動く。
- 変換スクリプト（小さな node か python 1本）: `chapters/*.md` → `data.js`。元mdを直せば再生成できる。ただしファクトチェックによる修正は md 側に反映して一本化する。
- 進捗: `localStorage` に自動保存（現在位置、レッスン完了、クイズ結果、間違い履歴）。JSONの書き出し/読み込みボタンでバックアップ・移行。
- 太字 `**x**` は赤の太字、【ひっかけ】はオレンジ系で表示。

## 画面
- ホーム: 全体進捗、「続きから」ボタン、章一覧（完了/進行中/ロック）、総仕上げ、復習、誤り報告一覧。
- セッション: レッスン → ミニクイズ（○×中心、2〜4問）を2〜3セット。終了で位置保存。1セッションの目安は読了5分 + クイズ含め30分以内になるよう、小項目を束ねて分割。
- 章末テスト: 五肢選択、採点と解説、70%でクリア。
- 総仕上げ: 本番形式、タイマー付き、採点と分野別の成績。
- 復習（別メニュー）: 間違えた問題だけを出す。
- 「これ間違いでは?」ボタン: 各レッスン/問題に付け、メモと共に保存・書き出し可能（後で Claude に渡して修正）。

## 作り手の判断（利用者に確認済みでない点）
- 章クリア基準を正答率70%としたのは作り手の判断。変更可能にする。
- 模擬試験の制限時間は本番の最新の受験案内で確認して設定する（現時点で断定しない）。
- 確認クイズは、既存の○×問題を、Claudeが章ごとに読んでレッスンへ割り当てて使う。割り当ては md の各Q行に `<!-- sec: 見出し名 -->` のタグで書き込む。束ねた後のレッスンに問題が0問の場合のみ新規に作る（最小限）。新規作成問題は事実確認の対象に含める。
- 学習単位の分割: 小項目を順に束ね、解説が約3,000〜4,000字になるまで足す。章をまたいで束ねない。極端に長い小項目は単独にする。
- 進捗は `gaimuin.progress.v1` の1キーに保存（位置、完了レッスン、クイズ結果、間違い履歴、章末テスト結果、誤り報告）。レッスンと問題には、内容に依存しない安定ID（章番号+通し番号）を振る。保存先はブラウザ・保存場所ごとに分かれるため、JSON書き出しでバックアップできる。
- 章ロックで詰まったときの救済として、設定に「全章を開放する」ボタンを置く。
- 模擬試験の制限時間は未確認のため、設定値として「未確認」と表示する。出題は既存の問題から章の比率で抽出し、分野別成績は章単位で出す。
- Q5（受渡日）は問題文「4営業日目」と解説「3営業日目(T+2)」で表記が混在しているため、ファクトチェック時に統一する。

## 品質保証（ファクトチェック）
- 対象: 教材中の数字・期間・罰則・割合・定義・制度、および全問題の正解と解説。ひっかけに使われる数字を重点とする。
- 照合先は一次情報のみ: e-Gov法令検索、日本証券業協会、金融庁、JPX、国税庁など。受験サイト・ブログは根拠にしない。
- 実行: 章ごとの検証を**サブエージェント3並列**で行う（1回に3章ずつ、3+3+3+1の4回）。検証役は読み取り専用で、次の表形式で返す: 場所（章/見出し/Q番号）、現在の記述、判定（正/誤/要確認）、修正案、出典URL。修正は1か所でまとめて md に反映する（並列書き込みの衝突回避）。新規問題は、作成者と別のサブエージェントが検証する。md修正後は、タグと変換を必ず再実行する。
- 作業全体（変換、割り当て、アプリ作成、検証、確認）は専門のサブエージェントに委任する。
- 修正は `chapters/*.md` に反映し、変更点を「修正一覧」（平易な言葉）にまとめて利用者に報告する。
- 一次情報で確認できなかった箇所は、断定せず「要確認」の印を付けるか外す。
- 法改正（NISA、税率、消費者契約法等）で古い箇所は最新の内容に直す。

## 作業の順序
1. 変換スクリプトと最小アプリを作る（現行の md のまま動作確認）。
2. 小項目ごとの問題割り当てと不足問題の作成。
3. ファクトチェック（3章ずつ並列）、修正反映、データ再生成。
4. 総合の動作確認（全章通し、保存/再開、模擬試験）。

## 残る限界
- 本番の出題とは完全には一致しない。誤りゼロは保証できない。
- 試験直前に、日本証券業協会の最新の受験案内で試験範囲・形式の変更がないか確認する必要がある。
