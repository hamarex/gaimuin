# 証券外務員一種 学習アプリ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `chapters/*.md` から、解説→確認クイズを繰り返す30分完結の学習アプリ（簡易HTML、ローカル動作、進捗保存、章末テスト、模擬試験）と、事実確認済みの教材データを作る。

**Architecture:** Node（依存なし）の変換スクリプトが md を `app/data.js`（`window.DATA`）に変換。`app/logic.js`（純粋ロジック、`node:test` でテスト）と `app/index.html`（UI。`logic.js` と `data.js` を `<script src>` で読む）。ファクトチェックは読み取り専用の検証役サブエージェントを3並列で走らせ、修正は1か所にまとめて md に反映して再生成する。

**Tech Stack:** Node 18+（`node:test`、外部パッケージなし）、素のHTML/CSS/JS。

**Spec:** `docs/superpowers/specs/2026-11-10-study-app-design.md`

## Global Constraints

- 外部ライブラリ・ネット接続・サーバ不要。`app/index.html` を `file://` で開いて動くこと（`fetch`/ES modules 禁止）。
- 入力は `chapters/[0-9][0-9]*.md` のみ（`00_header.md` は除外）。`merge.sh`、`index.html`、`gaimuin-ichishu.md`（ルート）は入力にしない。
- 素材の実数: `####` 小項目252個、○×286問（章別 25/30/24/28/36/23/22/28/40/30）、五肢87問（章別 8/10/8/8/8/8/9/8/10/10）。
- 本番形式: ○×70問×2点 + 五肢30問×10点 = 440点満点、308点以上で合格。
- 章クリア基準は正答率70%（設定で変更可）。制限時間は「未確認」と表示。
- レッスン: 小項目を順に束ね解説約3,000〜4,000字。章をまたがない。確認クイズは束ねたレッスンごとに割り当てた全問（目安2問以上）、0問のレッスンだけ新規作成。
- `**太字**` → 赤の太字、`【ひっかけ】` → オレンジ系。`<!-- markmap: fold -->` は除去。
- 進捗は localStorage キー `gaimuin.progress.v1` の1つ。ID は章番号+通し番号（例 `c02-ox-05`、`c02-mc-03`、`c02-l04`）で内容に依存しない。
- 事実確認は一次情報（e-Gov法令検索、日本証券業協会、金融庁、JPX、国税庁）のみを根拠とする。
- コミットは利用者の指示があるまで行わない。作業は専門のサブエージェントに委任する（検証は3並列）。
- ドキュメント（`README.md`、`docs/factcheck/summary.md`、利用者向け報告文、設計書・計画書の更新）はすべて `doc-writer` サブエージェントに書かせる。

## Review Focus

1. localStorage が使えない/壊れた JSON のとき：アプリは落ちず、進捗なしの状態で起動し「保存できません」と表示する。
2. 古い/不正な進捗ファイルを読み込んだとき：`version` 不一致や欠損は拒否して既存の進捗を保持する。
3. 問題のタグが無い/誤っている（`sec` が存在しない見出し）：変換がエラーで止まり、該当Q番号を表示する（黙って落とさない）。
4. md を直して再生成しても ID が変わらない（既存の進捗がずれない）。
5. 未回答のまま模擬試験を終了：未回答は0点で採点し、落ちない。

## File Structure

- `tools/parse.mjs` — md→構造化データの純粋関数（`renderInline`, `parseChapter`, `bundleLessons`）
- `tools/build.mjs` — `chapters/` を読み `app/data.js` を生成。検証（タグ、件数）もここ
- `tests/parse.test.mjs`, `tests/build.test.mjs`, `tests/logic.test.mjs`
- `app/logic.js` — 採点、進捗、解放判定、模擬試験の出題・採点（UI非依存）
- `app/index.html` — 全画面（ホーム/セッション/章末テスト/模擬試験/復習/設定/誤り報告）
- `app/data.js` — 生成物（手編集しない）
- `docs/factcheck/` — 検証結果の表と「修正一覧」

### Task 1: 変換（パーサ + data.js 生成）

**Files:**
- Create: `tools/parse.mjs`, `tools/build.mjs`, `tests/parse.test.mjs`, `tests/build.test.mjs`
- Output: `app/data.js`

**Interfaces:**
- Produces（`tools/parse.mjs`）:
  - `renderInline(md: string): string` — HTMLエスケープ後、`**x**`→`<b class="key">x</b>`、`【ひっかけ】…`→`<span class="trap">…</span>`、`<!-- … -->` 除去
  - `parseChapter(mdText: string, choiceText: string, no: number): Chapter`
  - `bundleLessons(sections: {title:string, md:string}[], maxChars = 4000): Lesson[]` — 章をまたがず順に束ねる。極端に長い1小項目は単独
- Produces（データ形、`window.DATA = { chapters: Chapter[] }`）:
  - `Chapter {no, title, lessons: Lesson[], ox: Ox[], mc: Mc[]}`
  - `Lesson {id:"c02-l03", title, sections:string[], html}`
  - `Ox {id:"c02-ox-05", text, answer:boolean, explain, sec:string|null}`（`sec` は元md内 `<!-- sec: 見出し名 -->` から）
  - `Mc {id:"c02-mc-03", stem, items:{label,text}[], choices:string[], answer:number, explain:string[], tip:string|null}`
  - レッスンの `sections` は `####` 見出し名の配列。「試験での出方」「暗記すべき数字・罰則」（`###`）はそれぞれ独立のレッスン

- [ ] **Step 1: テストを書く** `tests/parse.test.mjs`: `renderInline("**12時間**")==='<b class="key">12時間</b>'`、`renderInline("<script>")` がエスケープされる、`parseChapter` で第2章が `ox.length===30`・`mc.length===10`・先頭Qの `answer===true`、`bundleLessons` が4,000字超の小項目を単独にし、章をまたがない。`tests/build.test.mjs`: 全体で ox=286、mc=87、`####` 由来の `sections` 合計=252。
- [ ] **Step 2: 失敗確認** `node --test` → FAIL（モジュールなし）
- [ ] **Step 3: `tools/parse.mjs` を実装**（上記シグネチャ。Qの `答え：○/×` と `解説：`、五肢の `答え：**N**` とイ〜ニの解説行・`絞り込みのコツ` を取り出す）
- [ ] **Step 4: `tools/build.mjs` を実装**。`node tools/build.mjs` で `app/data.js` を出力。Review Focus 3 のとおり、`sec` が付いた Q で、該当見出しが存在しないものがあれば Q番号付きでエラー終了する（タグ無しは許可し、警告件数を表示）。
- [ ] **Step 5: 通過確認** `node --test` → PASS、`node tools/build.mjs` が `ox=286 mc=87` を表示

### Task 3: アプリのロジック（`app/logic.js`）

**Files:**
- Create: `app/logic.js`, `tests/logic.test.mjs`

**Interfaces:**
- Produces（`window.Logic` と `module.exports` の両方）:
  - `gradeOx(q: Ox, ans: boolean): {correct: boolean}`、`gradeMc(q: Mc, ans: number): {correct: boolean}`
  - `emptyProgress(): Progress`、`loadProgress(storage): {progress: Progress, ok: boolean}`、`saveProgress(storage, p): boolean`（失敗しても例外を投げない）
  - `importProgress(json: string, current: Progress): {progress: Progress, error: string|null}`
  - `Progress {version:1, position:{ch,lessonId}|null, lessonsDone:string[], quizResults:Record<string,{correct:boolean,ts:number}>, wrongLog:string[], chapterTest:Record<number,{score:number,passed:boolean}>, reports:{id:string,memo:string}[], settings:{passRate:number, unlockAll:boolean}}`
  - `isChapterUnlocked(p: Progress, no: number): boolean`（前章が `passed` か `unlockAll` か 第1章）、`examUnlocked(p, data): boolean`
  - `buildExam(data, rng: ()=>number): {ox: Ox[], mc: Mc[]}`（○×70、五肢30。章の問題数に比例して抽出、重複なし）
  - `scoreExam(exam, answers): {points:number, max:440, pass:boolean, byChapter:Record<number,{correct:number,total:number}>}`（未回答は0点、308点以上で合格）

- [ ] **Step 1: テストを書く** 例: `scoreExam` — ○×70問全正解+五肢0 → 140点・不合格、全正解 → 440点・合格、未回答のみ → 0点で例外なし。`loadProgress({getItem:()=>"{broken"})` → `ok:false` かつ `emptyProgress()`。`importProgress('{"version":2}')` → `error` ありで `current` 維持。`isChapterUnlocked` — 第1章は常にtrue、第2章は第1章 passed 後に true、`unlockAll` で全て true。`buildExam` → ox=70、mc=30、ID重複なし。
- [ ] **Step 2: 失敗確認** `node --test tests/logic.test.mjs` → FAIL
- [ ] **Step 3: 実装** 上記シグネチャどおり。localStorage キーは `gaimuin.progress.v1`。
- [ ] **Step 4: 通過確認** → PASS
